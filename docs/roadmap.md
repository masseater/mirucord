# mirucord ロードマップ

まだ作っていない機能と、その要件だけを書く。作り終えた機能はここから消す。
規模と性能の前提は AGENTS.md「想定規模と性能要件」に従う。

## 時間内に終わらない検索の呼び直し

一定時間で終わらない検索は、途中で ID を返し、その ID で呼び直してもらう。MCP の tasks 拡張は前提にしない。
各リクエストは 3 分以内に返す。

## 定型句の集計を R2 に移す

鯖内の定型句の集計（投稿ごとの HMAC と集計結果）も、鯖ごとの小さなファイルとして R2 に移す。集計し直しは Queue の consumer で行う。

## 鯖の言葉の注釈

`list_server_phrases` は語ごとの注釈を返す。残りは次の 2 つである。

鯖全体について「何の場か」「チャンネルの使われ方」を数行で書き、入力はチャンネル名と投稿数の分布にする。入力のハッシュをキーにして保存し、入力が変わったときだけ書き直す。「誰がどんな人か」は書かない（Developer Policy 16）。
管理者は管理画面で注釈を読み、語ごとに上書きでき、上書きは生成で消えない。

## メッセージの DL

取り込んだメッセージをまとめて DL できるようにする。
管理者だけでなくメンバーも DL できる。管理者が取り込みに同意するとき、メンバーの DL もその同意に含める。

## 課金

Developer Policy 18 は API Data の販売・商業化を禁じる。課金は機能（プランに含む DL 回数、または DL の権利の都度購入）に付け、データの件数に値段を付けない。
Developer Policy の Monetization Requirements は、Premium Apps の対応地域で有料機能を Discord 経由でも同価格以下で売ることを求める。日本は対象外だが、「地域」が開発者と購入者のどちらを指すかは規約から決められないので、併設するかを決める。

## Message Content intent の審査

利用者が 1 万人を超えると Message Content intent は審査制になり、毎年再審査がある。審査で用途とデータの扱いを説明できるようにする。

## ドメイン

本番を masseater.dev のサブドメインのまま続けるか、mirucord 専用のドメインを取るかを決める。
決まったら、そのドメインで Developer Portal の Privacy Policy URL と Terms of Service URL を設定する。Privacy Policy URL は Developer Terms of Service 5(a) が求めている。
